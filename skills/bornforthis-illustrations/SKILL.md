# Bornforthis 蜡笔手绘正文配图

## 核心定位

为中文内容设计和生成 16:9 横版正文配图。把关键判断、流程、结构、状态或隐喻变成一张清爽、有创意、可读但不说明书的手绘解释图；不要做成商业插画、PPT 信息图或课程课件。

默认视觉 IP 是 Bornforthis：钴蓝短刺发、外扩圆耳、纸白圆方脸、黄色圆脸颊和极简蓝色五官的青年男性角色。Bornforthis 必须参与画面的核心动作，不能只在旁边充当贴纸。

固定的是角色身份，不是造型。衣服、耳机、鞋、包、相机、书和其他配饰或道具都必须按当前主题重新选择，不得默认沿用参考图。

## 读取参考

按任务阶段读取对应文件：

- 任何生成或角色重绘前，先读 `references/bornforthis-ip.md` 和 `references/style-dna.md`。
- 规划配图和发明隐喻时，读 `references/composition-patterns.md`。
- 写生图或改图提示词时，读 `references/prompt-template.md`。
- 每张图生成后，读 `references/qa-checklist.md` 并逐项检查。
- 需要视觉校准时，先读 `references/example-index.md`，再按问题选择 `assets/examples/` 中最多 1–2 张查看；不要一次加载整套。

`assets/examples/` 内置 14 张 Bornforthis 成品参考图，覆盖两个断点、按目的分拣、信息压缩、因果链条、抽象到具象、对比差异、流程步骤、核心锚点、笔记回流、信息井、创意压机、内容发酵、系统承重和信任桥。它们只校准白底、纹理、描边、留白、角色一致性、换装范围与角色参与度，绝不充当默认构图模板。

每次新生成都必须在同一个 `image_gen` 调用中同时传入以下两张身份参考图；不能只传一张：

- `assets/references/bornforthis-ref-1.png`：面部与头部身份参考。
- `assets/references/bornforthis-ref-2.png`：全身比例与动作参考。

只从两张参考图读取固定面孔、发型、耳朵、五官、比例和手绘质感。不要复制其中的黄色背景、白色贴纸外沿、耳机、服装、鞋、相机、包、书、姿势或周围符号。

区分两类内置图片：

- `assets/references/` 是身份锚点：每次生成必须同时传入两张。
- `assets/examples/` 是成品视觉样例：仅在需要校准时查看；默认不传给 `image_gen`。若文字规范与样例冲突，以文字规范和两张身份锚点为准。

## 工作流

### 1. 消化正文

先读用户提供的正文、链接、文档或截图，提炼：

- 核心观点。
- 承担认知转折的段落。
- 适合用图解释的认知锚点。
- 只适合文字、不需要图的内容。

不要平均配图。优先选择核心判断、断点、输入输出闭环、分流、前后对比、承接路径、常见坑和角色状态变化。

### 2. 输出配图策略

如果用户只要求“分析怎么配图 / 思考哪些地方需要配图”，先给 shot list。每张图写清楚：

- 放在哪个段落后。
- 图的主题与核心意思。
- 结构类型。
- Bornforthis 正在做什么。
- 建议元素与中文标注词。

默认 4–8 张；短文 1–3 张；长文也不要轻易超过 9 张。

### 3. 单张生成

如果用户明确要求“生成 / 输出 / 做图 / 帮我生成”，不要停下来等确认。每张图单独调用 `image_gen`，不要拼成组图。

执行这些硬规则：

1. 将 Bornforthis 的完整身份描述放在提示词最前面。
2. 同时传入两张固定参考图；把它们声明为“身份参考，不是服装或构图参考”。
3. 根据主题设计当次衣服与配饰；无语义需要时不要自动添加耳机、相机、书或参考图中的套装。
4. 每张图只表达一个核心结构。宁可简化背景，也不能牺牲角色身份精度。
5. 保持 16:9、纯白背景、深蓝手绘粗描边、所有色块可见蜡笔斜线纹理、少量蓝红中文短批注和大量留白。
6. 不复刻参考图姿势或旧案例；从当前正文重新发明一个奇怪但成立的隐喻。

### 4. 检查与迭代

按 `references/qa-checklist.md` 检查。出现身份漂移、服饰被错误固化、纯色平涂、黄色背景、画面太满、PPT 感、中文过多或错字、左上角类型标题时，优先局部编辑或重生成。

编辑只涉及删除文字或清理背景时，保护角色和构图不变；编辑会重绘 Bornforthis 时，把目标图与两张固定身份参考图一起传入。

### 5. 保存交付

在 workspace 内工作时，把最终图保存到：

```text
assets/<article-slug>-illustrations/
```

按顺序命名：

```text
01-topic-name.png
02-topic-name.png
```

保留原始生成文件，不覆盖已有资产，除非用户明确要求替换。

## 输出口径

生成前的策略要短而准。生成后的交付包含生成数量、每张用途、保存路径，以及哪些图最稳、哪些图可选。不要长篇解释风格理论。
