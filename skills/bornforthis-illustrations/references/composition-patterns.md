# 构图模式与原创规则

## 基础结构类型

每张图只选择一种主结构，不要混太多。

### Workflow 流程

适合：输入 → 处理 → 输出、内容生产、AI 工作流、自动化链路。

画法：左侧输入，中间由 Bornforthis 或一台怪机器处理，右侧输出；橙色箭头表达主流向。

### 系统局部

适合：信息来源、过滤器、数据库、渲染器、Agent 系统局部。

画法：只画 3–5 个核心模块，Bornforthis 亲手操作其中一个关键环节。

### 前后对比

适合：混乱/有序、手动/自动、分散/收拢、焦虑/稳定。

画法：左侧混乱，右侧稳定，中间用一个自然动作或橙色流向连接。可以夸张角色状态，但不能改变固定身份。

### 角色状态

适合：用户痛点、创作者状态、工具太多、信息焦虑、卡住到跑起来。

画法：2–4 个 Bornforthis 状态，每个状态只表达一个动作并配一个短标注。不同状态可以换姿势或临时道具，但保持同一面孔。

### 概念隐喻

适合：内容工厂、信息仓库、脑内黑盒、工作流机器、自动日报。

画法：一个大的怪物件或低科技机器，少量输入与一个输出。Bornforthis 负责让它运转。

### 方法分层

适合：方法论框架、系统层级、能力栈、内容系统分层。

画法：一层层盒子或物件，不做正式金字塔；Bornforthis 搬砖、搭建或检查其中一层。

### 地图路线

适合：从想法到上线、用户路径、内容承接路径、学习路线。

画法：一条弯曲路径和少量节点；Bornforthis 牵线、开门、跨越或修补路线。

### 小漫画分镜

适合：失败到成功、真实过程、吐槽、使用前后变化。

画法：2–4 个小场景，每格只表达一个动作；服装可随时间和环境合理变化，但角色身份不能漂移。

## 原创隐喻生成法

每次都从当前文章重新发明隐喻，不能照搬参考图或旧图。

1. 把抽象概念换成物理动作：卡住、漏掉、变重、分拣、沉淀、发酵、开门、折叠、拆包、回流。
2. 把系统结构换成低科技物件：旧机器、纸箱、抽屉、水管、邮筒、怪表盘、秤、井、梯子、工位。
3. 让 Bornforthis 承担动作：卡进机器、守门、搬运、修补、称重、扶梯、记录或把东西塞进怪装置。
4. 按动作决定服装和配饰；只加入有语义作用的造型，不复刻参考图套装。

## 可用物件池

- 纸箱、抽屉、旧机器、漏斗、秤、邮筒、门、井、梯子、水管、线团、闸门、转盘、黑盒、打孔器、压面机、晾衣绳、怪工位。
- 每张图只选 1–2 个主物件，不要堆满。

## 动作池

- 拉、扛、塞、捞、压、称、缝、剪、拧、守、推、接、拆、标记、回收。
- 动作必须服务核心意思，不能只为了怪。

## 反复刻规则

两张身份参考图只校准角色，绝不是构图模板。除非用户明确要求，否则不要复用参考图中的半身点赞、正面站立、黄底英雄照、代码/音乐/相机/书本符号或固定穿搭。

`assets/examples/` 中的成品图也只用于视觉校准。即便新主题与某张样例名称相同，也要重新发明主物件、动作与空间关系；不要照抄断线、分拣台、手压机、链条、抽象云、天平、三步圆台、同心锚点、笔记回流泵、信息井、发酵罐、承重支架或信任桥。

也不要直接复用这些常见旧构图：

- 传送带上的两个断点。
- 角色在内容机器里拉判断杆。
- 角色变成漏斗分拣流量、信任和转化。
- 切“素材鱼”。
- 牵一条承接路径。
- 拉三层信息源。
- 三个分身分别拿喇叭、搭桥、开门。
- 盖章话术工具箱。
- 举牌看常见坑路径。

同类主题必须换新隐喻。例如“承接路径”可以画 Bornforthis 把内容尾巴接到门把手；“一鱼多吃”可以把一个纸团压成几种形状，而不必画鱼。
