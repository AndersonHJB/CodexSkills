# 构图模式与原创规则

## 基础结构

每张只选择一种主结构。

### Workflow 流程

适合输入、处理、输出、自动化和内容生产。使用一条清楚的阅读主线，让 Bornforthis 亲自搬运、连接或操作中间环节。

### 系统局部

适合信息源、过滤器、数据库、渲染器和 agent 局部。只保留 3–5 个核心模块，让角色参与一个关键动作。

### 前后对比

适合混乱/有序、手动/自动、分散/收拢和焦虑/稳定。避免正式表格边框；用动作和物件变化完成对比。

### 角色状态

适合用户痛点、创作者状态、工具过多、信息焦虑和卡住到跑起来。使用 2–4 个小场景，每个场景一个动作。

### 概念隐喻

适合内容工厂、信息仓库、脑内黑盒、工作流机器和自动日报。选择一个低科技、可手动操作的记忆物件。

### 方法分层

适合方法论、能力栈和系统层级。使用盒子、抽屉、台阶或积木，不画正式金字塔。

### 地图路线

适合从想法到上线、用户路径、内容承接和学习路线。使用一条弯曲路径与少量节点，让角色铺路、接线或修补。

### 小漫画分镜

适合失败到成功、真实过程和使用前后变化。使用 2–4 个无边框小场景，每段只表达一个动作。

## 原创隐喻生成法

1. 把抽象概念换成物理动作：卡住、漏掉、变重、分拣、沉淀、开门、折叠、回流、搭桥或修复。
2. 把系统换成低科技物件：纸箱、抽屉、手摇机器、漏斗、秤、邮筒、门、梯子、水管、转盘、压机或滑轮。
3. 让 Bornforthis 亲手执行动作：拉、扛、塞、捞、压、称、缝、剪、拧、推、接、拆、标记、测试或回收。
4. 判断真实物体是否需要材料色或状态色；有语义再加入辅助色。

每张通常只使用 1–2 个主要物件。保持动作明确，不为了热闹堆叠道具。

## 服装与配饰

- 根据动作选择简洁成年服装，不设置永久制服。
- 只有在音频、音乐、专注或降噪主题中使用耳机。
- 只有在摄影或采集主题中使用相机与相机包。
- 只有在学习、研究、写作或记录主题中使用笔记本。
- 让服装和道具服务动作，不遮挡蓝碎发、白脸和黄腮红。

## 辅助色判断

- 真实材料：木材用棕色、金属用灰色、自然状态用绿色。
- 信息分类：可用青色、紫色、绿色等区分，但不要把画面变成彩虹表格。
- 状态语义：红色优先承担 CTA、警示和转折；不要让随机橙色或紫色抢走该职责。
- 身份区域：头发保持品牌蓝，脸保持纸白，鼻点和腮红保持品牌黄。

## 反复刻规则

不要默认打开或复刻 `assets/examples/`。示例只校准角色身份、蜡笔笔触、留白、字体语气和颜色层级。

除非用户明确要求复刻，不要直接照搬这些示例隐喻：

- 两个断点的传送轨道。
- 手摇最小闭环机器。
- 三路目的分流台。
- 一源多用变体机。
- 四节点承接路径。
- 三类信息源推杆。
- 扩音器/桥板/开门三段分镜。
- 结尾盖章工具箱。
- 三个损坏接头。
- 巨大降噪旋钮。
- 想法约束压机。
- 时间胶囊沉淀。
- 滑轮系统承重。
- 证据卡信任桥。

保留核心意思，重新选择物件、动作和空间关系。
