# QA Checklist

## 身份必过项

- 主角是年轻成年男性 Bornforthis。
- 短蓝碎发、纸白方圆脸、小黄鼻点和两枚黄腮红清楚。
- 遮住文字、服装和配饰后，仍能通过“蓝碎发 + 白脸 + 黄腮红”识别。
- 角色亲自执行核心动作，不只是角落装饰。
- 同图重复人物时保持同一脸型、发型、黄腮红和年龄感。
- 没有小黑、黑色怪物、替代角色、幼儿化、日漫化或真人化。

## 画风必过项

- 使用 16:9 横版。
- 背景为干净白色，不继承参考图黄底。
- 保持蜡笔/彩铅颗粒、断续排线、不规则边缘和白色贴纸边。
- 保持可爱但有品质、温暖、非 AI 光滑感。
- 主体约占画面 40%–60%，留白充足。
- 一张图只讲一个核心动作、结构、状态或隐喻。
- 不像 PPT、课程页、完整流程图或商业图库。

## 色彩必过项

- 品牌蓝承担身份、主轮廓、主结构和阅读主线。
- 黄色承担黄腮红、强调、装饰和高亮。
- 红色优先承担 CTA、标签、警示、断点和转折。
- 把蓝/黄/红 60/30/10 作为三个品牌色彼此的视觉层级，不当作整图像素配额。
- 允许有语义的材料色、分类色和状态色。
- 辅助色不重染头发、脸、鼻点或黄腮红，不形成无意义彩虹或第二套主品牌。

## 配件必过项

- 不默认添加耳机、蓝夹克、相机、相机包或笔记本。
- 只在主题需要时使用配件，并让黄腮红完整可见。
- 连续多张图片应出现服装变化，不能形成固定蓝夹克制服。

## 文字必过项

- 标签少、短、可读，无长段伪文字。
- 无须标题时不添加标题。
- 中文标题、英文装饰、手写注释和代码分别遵守汇文明朝体、Fraunces、Caveat、Fira Code 的角色分工。
- 未提供真实字体文件时，不声称已精确使用指定字体。

## 失败信号

出现以下情况时重生成或局部编辑：

- 黄腮红缺失、变色或被遮挡。
- 耳机或蓝夹克在无关主题中反复出现。
- 背景为黄、米色、渐变、摄影环境或复杂纹理。
- 只剩蓝黄红且真实物体被强行染色，或反过来辅助色完全抢走品牌蓝。
- 画面彩虹化、霓虹化、幼儿糖果化。
- 角色成为 Q 版娃娃、真人、3D 塑料公仔或光滑矢量。
- 元素、箭头、节点或文字太多。
- 中文错字严重、乱码或标签不可读。
- 与 `assets/examples/` 的构图过度相似。

## 迭代方法

- 身份漂移：重复两张参考图职责，强化不可变脸部特征。
- 太三色化：只为真实物体补充一个有语义的辅助色。
- 太花：删除无语义色，恢复蓝色主线和白色留白。
- 配件固化：删除不服务主题的配件并更换服装。
- 太 PPT：删标题、边框、网格和节点，改成一个物理动作。
- 文字错误：先局部编辑；错误过多时减少标签并重生成。

## 交付判断

高质量图片应让读者先认出 Bornforthis，再在一秒内看懂核心结构。若只能靠标题、耳机、蓝夹克或品牌名识别，判定不合格。
