# 从一张照片到完整个人 IP Skill：零基础实战教程

这篇文章复盘一套真实可复用的工作流：先从人物照片与喜欢的插画参考中提炼视觉语言，设计属于自己的角色，再把反复迭代过的流程封装成 Codex Skill，最后批量生成动作、全身、角度、情绪、行业与主题系列，并用一个离线 HTML 页面完成筛选。

它写给不会画画、不会配色、不会写提示词，也没有开发 Skill 经验的人。你不需要一次做对；真正可靠的方法，是先建立标准，再小批量试稿，确认后扩展，最后把规则固化。

## 1. 最终会得到什么

一套完整交付不只是一张“像本人”的头像，而是一个可以继续用于头像、社交媒体、课程、品牌、表情包与宣传物料的角色系统。

本 Skill 的默认完整配置包括：

- 1 套经典主题；
- 8 套每次重新抽取的随机主题；
- 2 套高明度浅色主题；
- 每套 8 张动作设计；
- 每套 1 张正面全身锚点；
- 每套 8 张完整角度；
- 每套 24 张情绪头像；
- 8 张独立行业全身角色；
- 分组拼图和全部图片总览；
- 一个可搜索、筛选、收藏、淘汰、放大和导出清单的离线 HTML 页面。

默认没有机构 VI 输入时是 `459` 张独立原图。提供一套机构或高校官方 VI，并按默认规则追加 8 套完整主题时是 `787` 张。

这些数量不是目标本身。批量的价值在于把原本需要多轮沟通的服装、动作、颜色和配饰方向一次摊开，让没有艺术经验的人也能比较和选择。

## 2. 参考别人的角色时，应该学什么

“参考画风”不等于把别人的角色换一张脸。安全且有设计价值的做法，是把参考图拆成抽象的视觉语法，再用自己的身份特征、服装、动作、配饰和主题重新组合。

可以学习：

- 线条是蜡笔、铅笔、墨线还是平滑矢量；
- 五官被简化到什么程度；
- 头身比例和留白关系；
- 背景是纯色、纸张纹理还是稀疏涂鸦；
- 色彩数量、明暗和冷暖关系；
- 角色外侧有没有白色剪纸边；
- 动作和小道具如何表达性格；
- 整体气质是童真、克制、幽默还是专业。

不要复制：

- 原角色独有的脸、发型、服装组合与轮廓；
- 具有识别性的蝴蝶结、徽章、Logo、标语或专属道具；
- 受保护的校徽、品牌标志、制服和标准字；
- 能让普通观众误以为是原角色衍生品的整体设计。

一个实用判断是：拿掉人物的脸以后，如果服装、轮廓、动作和配饰仍然像参考角色，就说明改得还不够。

## 3. 准备人物照片与风格参考

最少需要两类输入：

1. 一张清晰的人物参考照；
2. 一张你喜欢的插画风格参考。

人物照优先选择：

- 正面或接近正面；
- 五官无遮挡；
- 发型清晰；
- 光线均匀；
- 不使用强滤镜；
- 能看见肩部或上半身。

风格参考不负责定义人物身份，只负责帮助分析媒介、线条、上色、比例、背景和装饰语言。人物照才是身份与呈现方式的唯一来源。

如果你还有喜欢的颜色、行业、服装气质或官方 VI 手册，可以一起提供；没有也没关系，Skill 会随机抽取主题。

## 4. 提取人物 DNA

人物 DNA 是“无论换什么动作和衣服，都能认出是同一个人”的最小特征集合。不要写成文学描述，要写成能在图片中检查的特征。

建议从以下维度提取：

- 脸部外轮廓：圆、方、长、窄或圆方；
- 眉毛：平直、弧形、浓淡、眉间距；
- 眼睛：圆、杏形、细长、眼距；
- 鼻嘴：简化后的宽窄、嘴角和唇形；
- 发型：长度、分区、刘海、侧面和发际线；
- 年龄感：少年、青年、成熟；
- 体型轮廓：纤细、匀称、结实；
- 常态表情：平静、温和、活泼或严肃；
- 呈现方式：根据照片和用户说明自适配，不先写死性别。

最后压缩成 4 至 7 个最强识别点。例如：

```text
圆方脸、平直浓眉、杏形眼、短而浓密的黑色纹理发、两侧渐短、青年感、平静但不严肃。
```

不要把西装、眼镜、耳机等偶然出现的物品误认为永久身份特征，除非用户明确希望保留。

## 5. 提取画风 DNA

画风 DNA 描述“怎么画”，人物 DNA 描述“画谁”。两者必须分开。

建议记录：

- 媒介：蜡笔、彩铅、油画棒、马克笔或数字模拟；
- 线稿：粗细、是否抖动、是否有重复描线；
- 上色：平涂、留白、是否露纸纹；
- 五官：点、线、圆还是几何块；
- 肤色策略：真实肤色、纸白留白或低饱和色块；
- 边缘：白色剪纸轮廓、贴纸边或无边；
- 背景：单色底、抽象涂鸦密度和方向；
- 阴影：无阴影、少量排线或柔和块面；
- 禁止项：写实皮肤、3D、渐变、光滑矢量、文字和水印。

示例：

```text
稚拙的蜡笔和彩铅触感；线条有手画抖动；脸和手大面积纸白留白；
平面色块，无渐变和写实阴影；外侧有不规则白色剪纸边；背景是少量抽象涂鸦。
```

## 6. 写出角色设计宪法

在生成第一张图前，先写一份“不能随意改变”的角色宪法。它通常包含四组规则。

### 身份锁定

- 固定最强人物识别点；
- 不因主题变化更换脸型、年龄和发际线；
- 发型可以做合理的小幅造型，但不能变成另一个人；
- 不擅自增加胡须、眼镜、首饰或性别化配件。

### 画风锁定

- 固定媒介、线条、上色、剪纸边和背景涂鸦；
- 禁止写实、3D、渐变、复杂光影和光滑矢量；
- 每张图保持同一画面密度和留白方式。

### 设计变化范围

- 可以变化动作、服装结构、鞋履、主题色、小道具和涂鸦；
- 每个方案至少改变三个设计维度；
- 不能只换背景色就当成新设计。

### 输出锁定

- 每张图独立生成；
- 方形画布；
- 不把九宫格中的小格当作最终原图；
- 不出现文字、Logo、水印和无关人物。

## 7. 先做 8 张差异明确的试稿

第一次不要直接扩展几百张。先做同一画风的 8 个角色提案，用来确认角色方向。

8 张应当在以下维度上拉开差异：

- 发型整理方式；
- 动作轮廓；
- 上衣与外套结构；
- 标志性配饰；
- 道具；
- 背景涂鸦语言；
- 主次色关系；
- 性格表达。

推荐让 8 个方案覆盖：问候、思考、创作、运动、阅读、旅行、工作和休息。每一张都应该远看就有不同剪影。

不合格的 8 张通常只是：同一个站姿、同一套衣服、同一顶头发，再换八个道具或背景颜色。这种结果没有选择价值。

## 8. 选择锚点并锁定一致性

从首轮试稿中挑出最接近目标的一张，作为系列锚点。锚点不是必须复制的姿势，而是后续所有图的角色身份证。

锚点应锁定：

- 标准脸部几何；
- 标准发型；
- 主题的基础服装；
- 主色、辅助色和线稿色；
- 剪纸边与背景涂鸦密度；
- 正常状态下的身体比例。

后续角度图和情绪图都应引用同一锚点。动作图可以调整服装细节和发型整理，但必须仍然属于同一个角色系统。

## 9. 设计随机主题与浅色盲盒

随机主题的价值是打破用户原有偏好，让人看到没有主动想到的可能性。每次任务记录一个随机种子，再据此抽取颜色方向。

一个完整主题不只是色板，还应包含：

- 独立的服装轮廓；
- 8 个动作和道具概念；
- 一组鞋履与小配饰；
- 一套背景涂鸦词汇；
- 一张正面全身锚点；
- 可被角度图继承的不对称细节。

浅色主题要额外解决“颜色浅导致五官消失”的问题：背景和服装可以高明度，但线稿必须保持足够深的对比。两套浅色主题也必须是两套新设计，而不是把深色主题调亮。

如果用户说喜欢某个颜色，要在随机主题之后追加，而不是用它替换随机盲盒。这样既保留探索价值，也尊重明确偏好。

## 10. 扩展完整角色系统

每个启用主题默认扩展为 41 张：

```text
8 张动作设计
+ 1 张正面全身
+ 8 张角度
+ 24 张情绪
= 41 张
```

### 正面全身

头发、双手、双腿和鞋履必须完整入镜。角色正面站立，手臂和身体之间留出可读空间，不用大型道具遮挡服装。

### 八个角度

依次生成：正面、左前 45°、左侧、左后 45°、背面、右后 45°、右侧、右前 45°。

不要左右翻转。衣服口袋、发缝、肩带等不对称细节应随空间关系变化，背面不能出现正脸。

### 二十四种情绪

覆盖积极、认知、社交压力、负面与低能量状态。情绪变化主要来自眉、眼、嘴、脸颊和少量动作符号；不要为了表现生气或悲伤而改变脸型、发型和服装。

## 11. 加入行业与官方 VI 主题

行业全身图通过服装、姿态、道具和背景装饰表达领域，例如技术、教育、建筑、健康科学、商业咨询、科研、摄影媒体和环境规划。

它们是创意形象，不代表用户真的拥有执照、学位或机构身份。避免医疗红十字、军警徽章、政府标志、文字证书和真实公司 Logo。

使用高校、机构或品牌 VI 时：

1. 查找官方设计手册或官方色彩规范；
2. 记录文档名称、日期、色值和色阶关系；
3. 区分官方屏幕色与自行换算的近似色；
4. 只使用颜色与抽象视觉语言；
5. 默认不复制 Logo、校徽、标准字、制服；
6. 不暗示学历、任职、认证或官方背书；
7. 仍然设计 8 套不同服装、动作和装饰系统，不能只做 8 种紫色深浅。

## 12. 计算图片数量，避免失控

生成前先计算，不要边做边猜。

设：

- `S` 为启用的完整主题数；
- `P` 为每套启用模块的图片数；
- `I` 为独立行业全身数量。

则：

```text
总原图 = S × P + I
```

全功能开启时 `P = 8 + 1 + 8 + 24 = 41`。

本 Skill 提供确定性计算器：

```bash
python3 scripts/calculate_feature_plan.py
python3 scripts/calculate_feature_plan.py --brand-theme-count 8
```

默认结果分别是 459 和 787。拼图与 HTML 页面不计入独立原图数量。

## 13. 批量生成、保存与质检

推荐按 4 张一批生成。每批结束马上检查，只重新生成失败项，不要因为一张错误而重做整个系列。

目录建议：

```text
00-classic/
  01-designs/
  02-front-full-body/
  03-angle-views/
  04-emotions/
01-random-theme/
...
industry-full-body/
```

质检至少包括：

- 计划数量与实际文件数相同；
- 所有原图都是独立方形图片；
- 没有重复文件哈希；
- 人物身份与标准锚点一致；
- 正面全身没有裁脚、裁手；
- 八角度方向齐全且没有镜像冒充；
- 24 种情绪齐全且可读；
- 没有写实、3D、渐变、文字、Logo 和水印；
- 旧的已批准原图哈希保持不变；
- 废弃稿不进入交付计数。

已有满意图片时，先记录 SHA-256，再把新增内容写入新目录。不要覆盖、重命名、重压缩或重新保存旧图。

## 14. 制作总拼图与 HTML 选择页

当图片达到几十或几百张时，只看文件夹很难比较，因此需要两个不同工具。

### 总拼图

总拼图用于一眼浏览全部方向。每张独立原图只能出现一次，不能把分组拼图再次放入总拼图。

### HTML 选择页

HTML 页面用于真正做选择。它支持：

- 搜索文件名、编号和系列；
- 按动作、全身、角度、情绪和行业筛选；
- 按主题系列筛选；
- 调整缩略图密度；
- 放大查看原图；
- 上一张和下一张；
- 收藏与淘汰；
- 浏览器长期保存与持久存储申请；
- 重置；
- 导出 JSON 选择清单。

生成命令：

```bash
python3 scripts/build_selection_gallery.py \
  --root /absolute/output-root \
  --output /absolute/output-root/00-selection-gallery.html \
  --expected-count 459
```

扩展旧作品且原图位于另一个目录时，再传入：

```bash
--sha-manifest /absolute/BASELINE-SHA256.txt \
--workspace-root /absolute/project
```

双击 `00-selection-gallery.html` 即可打开，不需要部署网站。页面中的图片使用相对路径，因此移动成果时要连同图片目录和 `00-aiyc-logo.svg` 一起移动。

## 15. 把工作流封装成 Codex Skill

当你已经重复修改提示词、目录和质检规则，就该把流程做成 Skill。Skill 的目标不是保存一段“神奇提示词”，而是保存可重复执行的决策顺序、脚本、资产和检查标准。

本项目的结构：

```text
generate-personal-ip-avatars/
├── SKILL.md
├── README.md
├── agents/
│   └── openai.yaml
├── assets/
│   ├── style-reference.png
│   ├── series-anchor.png
│   ├── selection-gallery-template.html
│   └── 00-aiyc-logo.svg
├── references/
│   ├── feature-switches.md
│   ├── prompt-set.md
│   ├── theme-expansion.md
│   ├── industry-brand-expansion.md
│   ├── selection-gallery.md
│   └── zero-to-personal-ip-skill-tutorial.md
└── scripts/
    ├── calculate_feature_plan.py
    ├── draw_theme_seed.py
    ├── build_selection_gallery.py
    └── make-*-overview.sh
```

各部分职责：

- `SKILL.md`：写触发场景、核心工作流、强制规则和交付标准；
- `README.md`：给普通用户看的安装、数量、开关与复制教程；
- `references/`：按需读取的详细规则，避免主文件过长；
- `scripts/`：数量、随机抽取、拼图和 HTML 这类必须稳定执行的任务；
- `assets/`：风格资产、标准锚点、HTML 模板和 Logo；
- `agents/openai.yaml`：Skill 在界面中的名称、简介与默认提示。

## 16. 从零制作同类 Skill

### 第一步：确定触发语句

先收集用户会怎么说，例如：

```text
根据我的照片设计个人IP。
参考这张插画的媒介和画风，重新设计我的角色。
给我做八角度和表情包。
把已有的角色扩展成完整角色系统。
```

把这些使用场景写进 `SKILL.md` 的 description，这决定 Skill 什么时候会被调用。

### 第二步：初始化结构

```bash
python3 /path/to/skill-creator/scripts/init_skill.py \
  generate-personal-ip-avatars \
  --path ~/.codex/skills \
  --resources scripts,references,assets
```

如果 Skill 已存在，不要再次初始化，直接迭代现有文件。

### 第三步：先写最短可执行流程

主流程建议只有：输入检查、DNA 分析、功能解析、数量计算、主题抽取、锚点、批量生成、质检、拼图、HTML、交付。复杂细节分别放进 reference。

### 第四步：把易错步骤脚本化

下面这些事情不应每次靠模型临时心算或手写：

- 图片数量计算；
- 随机主题种子与抽取记录；
- 原图筛选；
- 拼图输入去重；
- HTML 数据生成；
- 预期数量不符时主动失败。

### 第五步：设计功能开关

本 Skill 的关键规则是：用户没有明确写“功能开关”、开启、关闭或“只要”时，默认全部开启；只有明确控制时才改变模块。开关中没有写出的项目仍保持开启。

机构主题是数据依赖功能：开关可以默认开启，但用户没有提供机构名称或官方 VI 时，实际数量为 0。

### 第六步：加入失败保护

- 生成前必须输出计划数量；
- 没有参考照时停止；
- 预期 459 张但只发现 458 张时，HTML 构建必须失败；
- 旧原图哈希变化时停止；

## 19. 常见失败与修正方法

### 八张看起来一模一样

原因：提示词只要求“不同”，没有规定差异维度。

修正：为每张预先分配不同动作轮廓、服装结构、发型整理、道具和背景涂鸦；要求至少三个维度变化。

### 角色像贴纸或冰箱贴

原因：白色边缘太规则、人物太居中、背景过空、图形过于光滑。

修正：改成不规则剪纸边、蜡笔压力变化、局部出界的涂鸦和更自然的动作重心。

### 越生成越不像本人

原因：后续图片只参考上一张生成图，身份误差逐代积累。

修正：每批都同时引用原人物照和同系列锚点；把 4 至 7 个身份特征写进每次调用。

### 情绪图变成 24 个不同的人

原因：提示词只描述情绪，没有写“表情之外什么不能变”。

修正：明确只改变眉、眼、嘴、脸颊与少量符号；锁定脸型、头发、服装、裁切、背景和色板。

### 背面仍然有正脸

原因：角度名出现了，但没有技术约束。

修正：单独生成每个角度；背面明确要求不可见正脸，并使用口袋、发缝和肩带等不对称细节检查方向。

### 浅色主题看不清

原因：背景、衣服、线稿同时变浅。

修正：只让背景和大色块高明度，保留深色线稿与局部高对比配饰。

### HTML 少图或混入总览

原因：用文件通配符直接收集，没有区分原图、预览和废弃稿。

修正：排除 `overview`、`preview`、`_discarded` 和 `00-` 资产；传入 `--expected-count`，数量不匹配立即失败。

### 收藏记录消失

原因：更换浏览器、主动清除浏览器数据或移动到不同存储环境。

修正：点击页面中的持久保存申请，并定期导出 JSON 清单。浏览器存储不是云端备份，主动清除数据仍会删除记录。

## 20. 下一步怎么精修选中的角色

批量阶段结束后，不要继续无限生成。把 HTML 导出的收藏清单归纳成一份最终标准：

- 选定一个脸与标准发型；
- 选定一套主服装和备用服装；
- 选定一个主色板；
- 选定 2 至 3 个标志性配饰；
- 选定标准正面全身；
- 选定头像裁切；
- 选定 6 至 12 个最常用情绪；
- 记录禁止出现的失败特征。

再用这份标准制作最终角色规范页、头像、社交媒体封面、表情包或品牌素材。探索阶段负责打开可能性，精修阶段负责收敛；两者分开，个人 IP 才会既有创意又稳定。

---

真正重要的不是一次生成多少张，而是把“我不知道自己喜欢什么”转化成可观察、可比较、可保存的选择过程。人物 DNA 保证像你，画风 DNA 保证统一，角色宪法防止跑偏，功能开关控制成本，自动质检守住完整性，而 HTML 页面让零基础用户也能从几百张方案中做出清楚的决定。
