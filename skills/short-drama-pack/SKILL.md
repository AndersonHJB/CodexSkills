# 短剧制作包

读剧本，把所有设计写进一份 `project.json`，再用 `scripts/render.py` 渲染出全部独立文件、`index.html` 查看页和一份校验结果。

为什么要先写一份数据再渲染：分镜里每个角色、每张场景图都要写成平台引用「@分组-名称」，上百处引用只要有一个字不一样，平台就对不上图。数据里只写短 ID（如 `[[H_AWARD]]`），渲染时统一展开，名称就不会错。渲染器还会核对时长、分镜数、台词有没有漏、场景参考图的出图顺序等，这些靠人眼查不全。

## 输入

- **剧本**：必需。可以是文件路径，也可以是粘贴的正文。
- **角色参考图**：可选，可以是真人照片或已有的角色图。有的话逐张打开看，从图里提取角色 DNA（脸型、五官、发型、体型、肤色、年龄感、常穿的衣服），不要凭名字想象。
- **风格**：默认「国漫3D半写实」。
- **画幅**：默认 21:9，提示词里写「电影宽银幕21:9横版」。
- **平台格式**：默认用下面「平台格式」一节的写法。用户给了别的格式，就改 `meta.segment_header` 和 `meta.shot_line`，可用的变量见 schema。
- **平台上已有的分组名或资产名**：用户已经在平台建好角色或场景时，照用他们的名字，不要另起。
- **输出目录**：默认在剧本所在目录下建 `<剧名>_制作包/`。

只有在真的无法继续时才提问，例如剧本里人物关系互相矛盾。其余能定的都自己定，写进 `meta.decisions`，最后告诉用户。

## 工作流程

### 1. 拆剧本

逐场读剧本，列出以下内容：

- 每个人物在每一场的造型和状态，例如居家、战损、裹毯子、换礼服。
- 每个地点在每一场的状态和时间，例如干净、进水、夜晚布置。
- 跟着人走的道具，以及它们在谁手里。
- 全部台词，按出现顺序逐字抄出，包括旁白和齐声。
- 舞台提示：音乐、音效、慢动作、快切、字幕、定格。

剧本没写清的时间线要按台词推出来，例如“中午就通了”说明救援是上午到的。推出来的结论写进 `meta.decisions`。

### 2. 设计

开始设计前，先读 `references/craft.md` 里对应的章节。那里记着每条规则的原因，以及踩过的坑。

1. **角色**：
   - 每个角色写一段固定的 DNA，再给他配一个主色。几个人的颜色要拉开，也要和他出场的场景主色调拉开。
   - 每种造型或状态做一个资产，资产名用 `角色名_造型`，例如 `老公_居家六视图`、`蓝天_救援版`。每个角色都要有定妆多视图和六表情。
   - 资产提示词优先用组装字段（`outfit`、`state`、`layout`），渲染器会自动拼上风格锁和 DNA，不会漂移。
2. **道具**：跟着人走、会出现在好几个镜头里的道具，给它一个 `id` 和一句固定外观 `desc`。分镜里写 `[[道具ID]]`，渲染时展开成同一段描述，每一镜的道具才长得一样。
3. **空间与场景**：
   - 先写空间设定，即每个地点里固定物件的位置和左右关系。
   - 再定场景图：每个“地点 × 状态 × 时间 × 机位”出一张，命名为 `地点_状态_时间`。主设定图先出，其余图从它派生。
   - 剧情需要的机位都要有图，包括门口、反打、低机位，以及揭晓纸面或屏幕用的插入镜头。
   - 给每张图写 `stand`：人在这张图里能站在哪、处于画面哪个位置。
4. **音色**：固定音色只写“天生的嗓子”，逐句表演指令另外写。每个角色在 `voices.characters` 里写明语速 `cps`，角色名要和 `characters` 逐字一致。
5. **分镜**：
   - 先定导演思路和音乐进出表（`music_cues`），再逐镜写。
   - 按场次切成片段，每个片段不超过 30 秒、最多 5 个分镜，每个分镜只用一张场景图。
   - 动作多的分镜写上 `beats`（动作数），渲染器会连同台词一起算时长。
   - 说台词的人写在那一句的主语位置，例如“[[W]]看着他说：“……””，渲染器靠它找说话人。

### 3. 写 project.json

字段说明见 `references/schema.md`。完整示例在 `references/examples/堵王加冕/project.json`，用 grep 或按需读取其中的片段对照写法，不必整份读。

示例是技能成型前做的，有几处是旧写法，新项目按 schema 来：

- 角色资产直接写了 `prompt`，没有用组装字段。
- 道具没有 `id`。
- 没有写 `stand`、`cps`、`beats`、`music_cues`。

剧本长、数据大时，可以把 `segments`、`scenes` 等拆到分文件，在 `project.json` 的 `include` 里列出，渲染时会合并。

### 4. 渲染与校验

```bash
python3 <本技能目录>/scripts/render.py <输出目录>/project.json
```

- **「错误」**：必须改到一个都不剩。
- **「提醒」**：逐条判断。语速偏紧的就加时长；一个分镜引用了两张场景图的就拆开。
- **「备注」**：列的是没被分镜或其他资产用到的场景和角色资产，确认是不是故意的。道具、表情图、音色不在其中。

每次改数据后都重新渲染。md 和 html 都由数据生成，不要手改，手改的内容下次渲染会被覆盖。

### 5. 自查

对照 `references/craft.md` 末尾的「审查清单」逐镜检查，查出的问题改进数据后重新渲染。按三个角度过：

- **剧本覆盖**：动作有没有漏，顺序对不对，表演基调有没有偏。
- **场景与状态连续性**：场景图已经生成的话，实际打开图核对；还没出图时，对照 `space` 和场景提示词的文字核对左右关系和人能站的位置。
- **时长与可生成性**。

能开子代理时，三个角度各派一个去挑错；不能时自己按三个角度各过一遍，交付时说明是自查的。

导演阐述里每一条全片性的说法，例如“全部固定机位”“全用 50mm”“暖黄主调”，都要拿 06 文件末尾的「镜头一览」逐镜对一遍。说了做不到的，要么改分镜，要么改阐述。

### 6. 交付

用几句话告诉用户：

- 输出目录，以及 `index.html` 可以直接用浏览器打开查看和复制。
- 角色、场景图、片段、分镜的数量和总时长。
- `meta.decisions` 里你替他定的事，`meta.unverified` 里没核实的事。
- 下一步：先出角色定妆图，再出场景，再在平台建名，最后粘贴分镜。

## 平台格式

默认格式来自用户使用的视频平台：

```txt
本片段场景设定在: @场景分组-场景名,@场景分组-场景名。生成一个由以下4个分镜组成的视频。
分镜1[时长: 8s]: 在@场景分组-场景名，全景，中心构图，平视机位，35mm……@角色分组-资产名……说：“台词”
分镜2[时长: 5s]: ……
```

- 片段头部的场景由渲染器按分镜里实际出现的顺序自动生成，不要手写。
- 每个分镜都以「在[[场景ID]]，」开头。
- 画面里每个角色在这个分镜第一次出现时，都写成 `[[资产ID]]`。
- 不在画面里的角色写成「画面外的某某」，不写引用，否则模型会把他画进来。
- 音色：平台能把音色绑在角色上时（例如角色卡片上有音色按钮），分镜里不写音色。不能绑定时，说话前写「用<短版音色>说」。

## 最容易出错的地方

以下是做《堵王加冕》和试跑《最后一单》时审查反复查出来的问题，细节见 `references/craft.md`。

- **场景图的状态必须和那一刻一致**：干净、进水、退水，清晨、中午、黄昏，都要对上。角色资产也一样，居家、战损、裹毯不能用错时间。
- **跟着人走的道具不画进场景图**：杯子、手套、工具都由角色带着，画进去合成人物后会出现两份。这些道具每一镜都用 `[[道具ID]]` 写出同一段外观。
- **每个分镜自给自足**：模型只看得到当前这一镜。两只手各拿着什么、两人离多远、上一镜移动过的东西（伞歪过去、袋子挂到手腕上）现在在哪，每镜都要重写。递东西、撑伞、碰触之前，先写两人走近。
- **揭晓纸面或屏幕**：机位放在看纸的人身后，纸面朝向他，纸面空白，字后期合成。
- **视频模型做不好的东西不写进提示词，留给后期**：字幕、定格、画面里的中文字。手机屏幕和写了字的纸要背对镜头。
- **画外音写清楚**：写明“嘴全程闭着”。拟声词不放引号里，否则会被人物念出来。
- **少用否定句**：例如“没有工具箱”反而会把工具箱招进画面，改写成正面描述，例如“双手握着疏通器”。
- **反打机位左右相反**：每个机位都写明画面左、中、右各是什么。
- **时长按台词和动作一起算**：台词秒数 = 字数 ÷ 说话人语速；动作按每个 1.5 到 2 秒；走一段路、骑车穿过画面按距离另算。
- **音乐的进和出只发生一次**：在 `music_cues` 里定好每一处进、出，在哪一镜被谁切断。切断之前的那几镜要写明音乐还在。
